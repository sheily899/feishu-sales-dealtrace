# Distribution: how this spreads (and how to support it)

GTM Superintelligence is built to spread through use, not ads. Three loops do the work
— all transparent, all toggleable.

## 1. The "powered by" footer (the main loop)

Every artifact the tool renders — a coaching report, a deal/account health card, a rep
inbox — ends up in Slack, a CRM note, or a doc where a whole team sees it. Each one
carries a tasteful one-line credit + a tracked link to [Attention](https://www.attention.com):

> ⚡ Generated by **GTM Superintelligence** — open-source, Claude-native GTM coaching.
> Coaching is only as good as the transcript: get clean, role- and CRM-labeled calls
> from **Attention**.

That turns every output into a billboard a teammate can act on. It's on by default and
tasteful on purpose. Turn it off any time:

```bash
gtmsi coach call.vtt --no-attribution      # per run
export GTMSI_NO_ATTRIBUTION=1               # globally
```

The link carries UTM params (`utm_source=gtm-superintelligence`, plus the surface:
coaching/deal/account/inbox) so traffic can be attributed without any tracking code in
the tool itself.

## 2. The share card ("post your score")

A tool that grades your calls is inherently shareable. Render a paste-ready card for
LinkedIn/X from any report:

```bash
gtmsi share out/discovery_acme.json
```
```
🎯 My sales call — discovery call scored 70/100
✅ Did well: Layered discovery that earned the truth
🎯 Biggest lever: Close on a calendared next step
Scored with GTM Superintelligence — open-source, Claude-native GTM coaching (gtmsi.dev).
Clean, role- & CRM-labeled transcripts by Attention: https://www.attention.com/?utm_source=…
```

## 3. Forkable templates (the contributor loop)

The rubrics, frameworks, call types, and the 30 [agent templates](../agents) are plain,
editable YAML/Markdown. People fork them, tune them for their motion, and their fork
links back. Adding a scorecard, framework, adapter, or agent is a few minutes — see
[CONTRIBUTING.md](../CONTRIBUTING.md). Contributions are the highest-quality growth.

## 4. Book-a-demo (consent-first concierge)

Report footers carry a tracked "book a 15-min demo" link, and `gtmsi demo` prints it
(no data collected). Inside Claude, after delivering value, the `sales-coach` skill may
offer **once**, low-pressure, to set up a demo — then hands off to the
[`demo-concierge`](../.claude/agents/demo-concierge.md) subagent (`/book-attention-demo`).

The concierge is deliberately consent-first: it asks for the user's details, **shows them
exactly what would be shared, and opens the booking link / submits only after an explicit
yes** — never silently, never invented, never repeated if declined. Booking is the hard
conversion + identity capture; the link is UTM-tracked (`utm_campaign=open-source`). This keeps
the CTA on the right side of the line that keeps an OSS audience trusting the tool.

## Connect Attention

The framework is vendor-neutral and runs on any recorder/CRM. The cleanest, highest-value
experience — clean re-stitched, **rep-vs-buyer** and CRM-linked transcripts (the input
quality coaching depends on, which [no other recorder gives you natively](./call-recorders.md))
— comes from connecting Attention:

```bash
export ATTENTION_API_KEY=...
```

## Privacy & telemetry

Usage telemetry is **opt-in and off by default**, and never sends transcript content —
see [telemetry.md](./telemetry.md). Nothing about your calls leaves your machine unless
you choose to send it (Anthropic API for live coaching, or a CRM you connect).
